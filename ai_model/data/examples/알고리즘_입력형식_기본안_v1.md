# 알고리즘 입력 형식 기본안 v1 (시뮬레이션 → 알고리즘)

작성 2026-10-22. 진행상황 2-5. 팀 알고리즘 담당의 답(`알고리즘_입출력_질문_2026-10-18.md`)을 기다리지 않고 **우리가 정해서 진행**하기로 한 결정(10/21)에 따른 **기본안**입니다. 팀 알고리즘과 맞지 않는 점이 있으면 6절의 질문에만 답해 주시면 바꿉니다. 코드 `frame_export_v1.py`, 자체 검사 `test_frame_export_v1.py`, 열 정의 `frame_schema_v1.json`, 예시 `예시_frames_v1.csv`, 경보 플래그 참고 구현 `alarm_flag_v1.py`(시험 `test_alarm_flag_v1.py`, 예시 `예시_frames_flag_v1.csv`)(모두 같은 폴더). 모든 숫자는 모델에서 읽습니다(`write_input_format_md_v1.py`).

## 1. 한눈에

- 시뮬레이션은 **프레임** 단위 표를 줍니다. 한 프레임은 모든 채널을 한 바퀴 읽은 것입니다: NIR 흡광도 3개 + 마이크로파 6개 주파수 × (|S21| dB, 위상 °) + NTC + FSR 힘. 정답(포도당, 두께, 온도)은 라벨 열, 세션 공통 오프셋은 "숨은 값" 열, 각 채널의 1σ 잡음은 sigma 열로 따로 줍니다.
- 노트북의 `wave [배치, 7, 100]` 모양이 필요하면 `--layout 7ch`가 7채널 × 창으로 바꿔 줍니다. 단 **100샘플 = 10초(10 Hz)는 이 하드웨어의 시간 예산과 맞지 않습니다**(3절).
- 이 데이터는 **파이프라인 시험용**입니다. 시뮬레이션으로 학습한 모델은 실기기에서 그대로 맞지 않습니다(5절). 제출물에도 그렇게 밝힙니다.

- 반대 방향(알고리즘 → 앱)은 **읽기와 별도로 잔차 값과 경보 플래그를 함께 내는 것**을 제안합니다(4-5절). 숫자는 그대로 두고 GUI가 "신뢰 낮음"을 표시합니다. 경보 기준은 벤치 반복 측정으로 맞춥니다(4-6절).

## 2. 질문서에서 확인한 것 (`알고리즘_입출력_질문_2026-10-18.md` 요약)

`04_알고리즘 층/알고리즘/`에 두 모델이 있고 서로 다릅니다. 노트북(`colab_training_pipeline.ipynb`)은 입력 2개(`wave` [배치, 7, 100], `phys` [배치, 6]), 폴더의 `glucose_model.tflite`는 입력 1개 [1, 7, 1]입니다. 둘 다 학습 데이터가 난수라서 학습된 모델이 아니라 자리만 잡아 둔 것으로 읽었습니다. 7채널의 정의, `phys` 6개의 정의, 샘플링 속도는 **아직 답이 없습니다.** 이 문서는 그 답이 없어도 시뮬레이션 쪽 출력을 정해 두려는 것입니다.

## 3. 시간 예산: 프레임이 몇 초마다 하나 나오는가

ADS1115 한 개(860 SPS)가 모든 채널을 번갈아 읽는다는 현재 회로 기준입니다. 한 프레임의 변환 횟수는 (LED 3개 × 읽기 2회(켬/끔) + 마이크로파 12 + NTC·FSR 2) = 20회에 평균 횟수 n을 곱한 값입니다(감시 PD 방식은 LED당 4회라서 26회). 아래 σ는 그 프레임 하나에서 이상적 추정기가 낼 수 있는 포도당 1σ(융합, 온도·두께 모름, 기준 상태 포도당 108 mg/dL, 팬텀 G01 중심값, 확산 근사)입니다.

| n (읽기당 평균) | 프레임 주기 [s], 설계 1 | σ 포도당 [mg/dL], 설계 1 | 프레임 주기 [s], 설계 2a | σ 포도당 [mg/dL], 설계 2a |
|---|---|---|---|---|
| 4 | 0.093 | 28.2 | 0.121 | 28.1 |
| 16 | 0.372 | 17.2 | 0.484 | 16.6 |
| 50 | 1.16 | 10.9 | 1.51 | 9.9 |
| 215 | 5 | 6.2 | 6.5 | 4.9 |
| 860 | 20 | 3.4 | 26 | 2.5 |

- 노트북의 "10초 = 100샘플(10 Hz)"를 지키려면 n ≈ 4.3, 즉 **n = 4**(프레임 주기 0.093 s)입니다. 이때 프레임 하나의 σ는 설계 1에서 28 mg/dL로, 설계값 n = 860(3.4 mg/dL)의 8.2배입니다.
- n을 215배 늘렸는데 프레임 σ는 8.2배만 줄었습니다(읽기 잡음만이면 √215 = 14.7배). 이유는 n으로 줄지 않는 항이 있기 때문입니다: NIR 흡광도 1σ는 n = 4에서 3.4~4.9×10⁻⁴ AU, n = 860에서 3.0~3.1×10⁻⁴ AU로 거의 줄지 않습니다(모델에서 LED 온도 변동 항이 n과 무관한 바닥). 크게 줄어드는 쪽은 마이크로파 읽기 잡음입니다(|S21| 1σ 1.2e-03 → 7.9e-05 dB, 위상 3.2e-03 → 2.2e-04 °).
- 그래서 n = 4 프레임 215개를 평균한 값은, 느린 변동이 프레임 사이에 상관되어 있다면 n = 860 읽기 하나보다 σ가 큽니다. 이 내보내기는 프레임 사이의 잡음을 **독립으로** 그리므로(5절) 평균하면 σ가 더 작게 나옵니다. 프레임 평균의 이득은 실제보다 낙관적입니다.
- 설계값(n = 860)에서는 프레임이 설계 1에서 20 초, 설계 2a에서 26 초마다 하나 나옵니다. 10초 창에는 프레임이 하나도 안 들어갑니다. 알고리즘이 어떤 창을 요구하는지가 6절의 첫 질문입니다.

- 마이크로파 주파수 f1~f6 = 2.30, 2.36, 2.42, 2.48, 2.54, 2.60 GHz. NIR 파장 = 1310, 1370, 1625 nm.
- **기준**: 흡광도 A와 NTC는 기준 상태(포도당 0 mg/dL, 공칭 두께 4 mm, 온도 변화 0) 대비입니다. |S21|과 위상은 절대값(케이블 위상 포함)입니다. FSR은 절대 힘입니다. 기준 상태 정의는 팬텀 단계용이며, 사람에게서는 이 기준을 잡는 방법이 따로 필요합니다.
- 흡광도 A는 기준 대비 값이라서 기기가 실제로 읽는 것(전압)에서 A로 바꾸는 단계(V_ref를 어떻게 잡는가)는 이 표에 들어 있지 않습니다. 알고리즘이 전압을 받는지 A를 받는지는 6절의 질문입니다.

### 4-2. 세션과 정답

한 세션 = 가상의 한 번 착용입니다. 세션마다 정해지는 것: 두께(기준 두께 ± 0.1 mm 정규분포, ±0.5 mm로 자름), 마이크로파 공통 오프셋 3개(이득, 위상, 케이블 길이; 모델의 사전 분포에서 뽑아 세션 내내 같음), 포도당 변화(시작 70~250 mg/dL, 기울기 −1~+1 mg/dL/분의 직선), 전자부 온도 상승(120 초 시정수의 지수 곡선, 최종 평균 0.5 °C), 착용 시간(시작 5분). 이것들은 시험용 **가정**이며 실제 사람이나 팬텀 실험의 분포가 아닙니다.

### 4-3. 7채널 창 (`--layout 7ch`)

채널 순서: `A_1310`, `A_1370`, `A_1625`, `S21_dB_f4`, `S21_deg_f6`, `ntc_dT_C`, `fsr_N`. 마이크로파는 6개 주파수 중 포도당 민감도/잡음이 가장 큰 것을 크기에서 f4(2.48 GHz), 위상에서 f6(2.60 GHz)로 골랐습니다(나머지 주파수는 쓰지 않음; 12채널 전부가 필요하면 wide 표를 쓰세요). 파일은 `이름.npz`(`wave` [N, 7, T] float32, `y` = 창 마지막 프레임의 포도당, `session`, `t_end_s`)와 `이름.json`(채널 이름, 창, 프레임 주기)입니다. 창은 세션 경계를 넘지 않습니다. 노트북의 `phys` 6개는 정의를 모르므로 만들지 않았습니다.

### 4-4. 정규화와 데이터 나누기 (제안)

- 정규화: 채널마다 **학습 세션**의 평균·표준편차를 구해 파일로 저장하고, 시험과 앱에서 같은 값을 쓰세요. 노트북 모델에는 입력 정규화 단계가 없습니다.
- 나누기: **세션 단위**로 학습/검증/시험을 나누세요(같은 세션의 프레임을 섞어 나누면 두께와 오프셋이 새어 들어가 시험 결과가 좋게 나옵니다). 6단계 팬텀 실험의 판 간격·재장착 회차에 해당합니다.
- 지표: MARD와 Clarke 오차 격자를 제안합니다(팀이 정한 것이 있으면 따르세요). 제출물의 문장은 "시뮬레이션 오차 분포의 95 %가 ±15 mg/dL 안"으로 씁니다.

### 4-5. 알고리즘 출력 기록: 읽기 + 잔차 + 경보 플래그 (제안)

입력(4-1절)과 반대 방향의 제안입니다. **알고리즘은 포도당 읽기 하나만 내지 말고, 같은 적합의 잔차 검사 결과를 별도 필드로 함께 내 주세요.** (2026-10-22 결정: 숫자는 그대로 두고, GUI가 "신뢰 낮음"을 표시하며, 설계 2b를 쓰려면 반드시 넣는 쪽.) 정의와 계산은 `alarm_flag_v1.py`에 있습니다.

| 필드 | 단위 | 구분 | 뜻 |
|---|---|---|---|
| `glucose_hat_mgdl` | mg/dL | output | 추정 포도당. 경보가 울려도 이 숫자를 지우거나 바꾸지 않고 그대로 냄 |
| `fit_converged` | 0/1 | resid | 적합이 수렴했으면 1. 0이면 아래 잔차 값도 믿지 않음 (이 경우 flag_model_mismatch를 1로 취급) |
| `resid_Q` | - | resid | 잔차 검사 값 Q = Σ((읽은 값 − 모델 값)/σ)² (사전 행 포함). 모델과 잡음 가정이 맞으면 κ²·χ²(dof)를 따름 |
| `resid_dof` | - | resid | 자유도 = 읽은 값 + 사전 행 − 모수 (프레임 형식의 융합 적합에서 12) |
| `resid_thresh` | - | resid | 경보 기준 κ²·χ²₍₁₋α₎(dof) |
| `resid_p` | - | resid | p값 = P(χ²(dof) > Q/κ²). 작을수록 모델과 어긋남 |
| `flag_model_mismatch` | 0/1 | resid | Q가 기준을 넘었으면 1 (모델 불일치 의심). 착용 감시 플래그 flag_wear와 별개 |
| `resid_alpha` | - | meta | 거짓경보율 α (모델이 맞는데 울릴 확률). 기본 0.01 |
| `noise_kappa` | - | meta | 잡음 배율 κ (실제/가정, 벤치 반복 측정으로 잰 값). 기본 1 |
| `resid_estimator` | - | meta | Q를 낸 추정기: E0 = 사람 단위 값 없음(이 폴더의 참고 구현), E1 = 사람 단위 값 포함(실제로 써야 하는 쪽) |

구분: output = 알고리즘이 내는 값, resid = 같은 적합의 잔차 검사, meta = 검사에 쓴 설정.

규칙:

1. **숫자는 그대로**: `glucose_hat_mgdl`은 경보와 상관없이 항상 냅니다. 읽기를 비우거나 바꾸는 것은 알고리즘이 아니라 표시 쪽이 정합니다. 추정 잡음과 잔차 Q는 서로 독립이라서, 읽기를 보류해도 내보낸 읽기의 잡음 부분은 바뀌지 않습니다(`오차한계_검출_v1.md` 3-2절).
2. **표시**: `flag_model_mismatch` = 1이면 GUI가 읽기 옆에 "신뢰 낮음"을 띄웁니다. FSR 착용 감시 플래그(`flag_wear`, `착용감시_v1.md`)와는 **다른 필드**입니다. 표시는 둘 중 하나라도 1이면 "신뢰 낮음"으로 하되 어느 쪽 때문인지 적습니다. 두 플래그를 하나로 합쳐 내보내면 원인 구분이 사라집니다.
3. **설계 2b**: S11 읽기 12개가 더해져 읽은 값 27개, 자유도 24입니다(`오차한계_검출_v1.md` 3-1절). 2b의 선형 하한은 비선형 적합에서 낙관적이어서(같은 문서 3-8절, 6절) 2b를 후보로 쓰려면 경보로 거른 뒤의 값을 함께 보고해야 하므로 **2b에서는 이 필드가 필수**입니다. 설계 1·2a는 권장입니다. 이 폴더의 내보내기는 2b를 지원하지 않습니다(S11이 통합 모델에 없음).
4. **어떤 적합이어야 하나**: 사람마다 다른 값(산란, 혈액층 물 비율, 피부 εr)을 미지수로 넣은 적합(E1)이어야 합니다. 그것이 없는 적합(E0)에 이 검사를 걸면 모델이 맞아도 사람 차이만으로 거의 모든 세션이 경보를 울립니다(α = 1 %일 때 ≈100 %, `오차한계_검출_v1.md` 3-5절 (가)). 이 폴더의 `--flag` 참고 구현은 E0입니다.
5. **설정**: 기본 α = 0.01(거짓경보율), κ = 1(잡음 배율). κ는 가정하지 말고 벤치 반복 측정으로 잽니다(4-6절). 사용한 α, κ, 추정기 종류를 매 기록에 같이 냅니다.
6. **제출 문구**: 경보로 거른 뒤의 분포를 인용할 때는 "내보낸 읽기 중"이라고 쓰고 내보내는 비율을 같이 씁니다. "시뮬레이션 오차 분포의 95 %가 ±15 mg/dL 안"에는 거르기 전 분포인지 후 분포인지를 밝힙니다. 경보가 없다는 말은 모델이 맞다는 뜻이 아닙니다(5절).

참고 구현의 시험: 위 필드를 예시 데이터 90프레임(`예시_frames_flag_v1.csv`, `--flag`)에서 E0 적합으로 만들면 Q 평균이 11.0(자유도 12), 경보가 0개입니다(α = 1 %이면 기대 0.9개). 이 프레임에는 사람 단위 변동과 장착 불량이 없어서 모델이 맞는 경우뿐입니다. 따라서 이 숫자는 **Q, 자유도, 기준 계산이 맞게 이어졌다는 확인**이지 불일치 탐지 성능이 아닙니다.

### 4-6. 경보 기준 맞추기: 잡음 배율 κ를 벤치에서 재기

κ = 실제 잡음 / 모델이 가정한 잡음입니다. 잡음을 실제보다 작게 가정하면(κ > 1) 모델이 맞아도 경보가 늘어납니다. 아래는 기준을 κ = 1로 둔 채 실제 잡음이 κ배일 때 모델이 맞는데 울리는 비율입니다(`alarm_flag_v1.false_alarm_rate`; `오차한계_검출_v1.md` 3-5절 (다)와 같은 값).

| 자유도 | α | κ = 1 | κ = 1.1 | κ = 1.2 | κ = 1.5 | κ = 2 | κ = 3 |
|---|---|---:|---:|---:|---:|---:|---:|
| 12 | 0.1 % | 0.10 % | 0.72 % | 2.90 % | 26.25 % | 76.71 % | 98.89 % |
| 12 | 1 % | 1.00 % | 4.14 % | 10.96 % | 47.40 % | 88.56 % | 99.61 % |
| 12 | 5 % | 5.00 % | 13.60 % | 26.40 % | 67.32 % | 94.89 % | 99.87 % |
| 24 | 0.1 % | 0.10 % | 1.20 % | 6.08 % | 53.48 % | 96.94 % | ≈100 % |
| 24 | 1 % | 1.00 % | 6.10 % | 18.99 % | 74.65 % | 99.07 % | ≈100 % |
| 24 | 5 % | 5.00 % | 18.16 % | 39.02 % | 88.13 % | 99.74 % | ≈100 % |

자유도 12는 설계 1·2a, 24는 설계 2b입니다. κ = 1.2만 되어도 α = 1 %의 거짓경보가 자유도 12에서 11 %, 24에서 19 %가 됩니다.

이 표는 잔차 전체가 κ배로 커지는 경우의 값입니다. 읽기 잡음만 커지고 사전분포(마이크로파 오프셋의 사전 행)는 맞으면 거짓경보는 이보다 조금 낮게 나옵니다(통합 모델의 적합을 300번 돌려 확인: `test_alarm_flag_v1.py` 7절). 그래서 이 표는 거짓경보를 넉넉하게 어림하는 값으로 읽으세요.

**언제 재나**: 경보 기준에 넣는 κ는 회로와 지그가 설계 상태(자동 범위, 평균 횟수 860, 고정 지그)에 가까워진 뒤의 값이어야 뜻이 있습니다. 지금 NIR 벤치는 수동 정렬 드리프트가 지배해서(`NIR_하드웨어_진행상황_2026-10-21.md`) 반복 변동이 모델 가정보다 훨씬 크므로 κ가 1보다 크게 나올 것으로 예상합니다. 그 값은 "벤치와 모델의 차이"를 보여 줄 뿐 경보 기준에 넣을 값이 아닙니다. 시뮬레이션만으로 내는 제출물에는 필요하지 않습니다.

**재는 순서** (`alarm_flag_v1.kappa_from_repeats`):

1. 같은 팬텀, 같은 장착, 같은 설정(평균 횟수 n 포함)에서 **아무것도 바꾸지 않고** 프레임을 M개 연달아 읽습니다. 프레임 주기가 20 s이면 M = 20이 약 7분입니다.
2. 채널마다 표준편차를 구해 모델이 가정한 1σ(프레임 표의 sigma 열)로 나눈 값의 제곱평균 제곱근이 κ입니다. 구간은 자유도 C(M − 1)의 카이제곱으로 구합니다. 연속 차분으로 구한 값(`kappa_diff`)도 같이 냅니다.
3. κ의 95 % 구간이 1을 포함하면 κ = 1로 둡니다. 포함하지 않으면 **가정한 σ를 실측에 맞춰 고치는 쪽이 먼저**입니다. 고칠 수 없으면 `noise_kappa`에 κ를 넣어 기준을 κ²배로 올립니다 (거짓경보는 α로 돌아오지만 같은 크기의 불일치를 알아채는 힘은 떨어집니다).
4. `kappa`가 `kappa_diff`보다 뚜렷하게(예: 10 % 넘게) 크면 반복 사이에 느린 드리프트가 있다는 뜻입니다. 두 값을 모두 기록합니다. 사용 중에는 이 드리프트도 Q에 잡음처럼 보입니다.
5. 이 값은 상태가 고정된 한 점에서의 것입니다. 신호 크기에 따라 달라지는 잡음 항이 있으므로 두께(판 간격)가 다른 몇 점에서 다시 재서 가장 큰 κ를 씁니다.

재는 횟수와 정밀도(κ̂ = 1일 때 95 % 구간, 채널이 서로 독립이라고 본 값이라서 채널 사이에 상관이 있으면 실제 구간은 더 넓습니다):

| 반복 M | 읽은 값 15개(설계 1·2a) 자유도 | 구간 | 읽은 값 27개(설계 2b) 자유도 | 구간 |
|---|---:|---|---:|---|
| 10 | 135 | 0.89 ~ 1.14 | 243 | 0.92 ~ 1.10 |
| 20 | 285 | 0.92 ~ 1.09 | 513 | 0.94 ~ 1.07 |
| 40 | 585 | 0.95 ~ 1.06 | 1053 | 0.96 ~ 1.04 |
| 100 | 1485 | 0.97 ~ 1.04 | 2673 | 0.97 ~ 1.03 |

## 5. 이 형식이 보장하지 않는 것

- 프레임 사이의 잡음을 독립으로 그립니다 (실제로는 느린 변동이 프레임 사이에 상관됨).
- 마이크로파 모델은 팬텀에만 있습니다.
- 진실과 추정이 같은 순방향 모델을 씁니다.
- 설계 2b(S11)는 통합 모델에 없습니다.
- 이 데이터로 학습한 모델은 실기기에서 그대로 맞지 않습니다 (파이프라인 시험용).
- 한 세션 안에서 두께는 일정합니다(실제로는 클립 힘과 크리프로 움직임). 숨은 교란(산란 변화, 공기층, 재장착)은 이 내보내기에 넣지 않았습니다(모델에는 `dist` 입력이 있어 필요하면 추가할 수 있습니다).
- 경보 플래그: 이 폴더의 참고 구현은 E0이고 예시 프레임에는 불일치가 없으므로, 경보율이 α 근처인 것은 계산 확인일 뿐 탐지 성능이 아닙니다. 실제 탐지력은 E1 적합과 실제 불일치의 분포가 있어야 말할 수 있습니다.
- 경보 플래그가 못 잡는 것: 마이크로파 혈당 계수가 가정과 다른 경우, 아주 작은 공기 틈 등(`오차한계_검출_v1.md` 3-4절, 4절, 5절). 경보가 없다는 것은 읽기가 맞다는 뜻이 아닙니다.
- 경보 기준은 잡음 배율 κ와 사람 단위 변동의 가정 크기에 민감합니다(4-6절, `오차한계_검출_v1.md` 3-5절). 둘 다 틀리면 거짓경보가 크게 늘거나 검사가 둔해집니다.
- 시뮬레이션 값은 가정이 많은 모델 값입니다(실측으로 검증되지 않음). 학습에 쓰는 경우 "시뮬레이션 데이터로 학습한 모델은 실제 기기에서 그대로 맞는다고 볼 수 없다"를 제출물에 밝힙니다.

## 7. 사용법

```
python frame_export_v1.py --sessions 20 --frames 60 --n-avg 860 --design 1 --seed 1 --out frames.csv
python frame_export_v1.py --sessions 20 --frames 120 --n-avg 4 --layout 7ch --window 100 --stride 10 --out win
python frame_export_v1.py --design 2a --noise 1.0 --ideal        # 잡음 없는 순방향 값
python frame_export_v1.py --sessions 3 --frames 30 --flag --alpha 0.01 --kappa 1.0 --out f.csv    # 참고 구현의 잔차 검사 열을 붙임
```
- `--design 1|2a`: 설계 칸(2b는 S11 채널이 통합 모델에 없어서 지원하지 않음). 2a는 NIR 평균이 n/2가 되는 "같은 시간" 설정이 아니라 같은 n으로 읽습니다(프레임 주기가 길어짐).
- `--flag`: 열을 붙이는 것은 wide 표만 됩니다(4-5절). `--alpha`, `--kappa`: 경보 기준(4-5, 4-6절).
- `--noise s`: 잡음 배율(1 = 모델 값). `--ideal`: 잡음 없음. `--seed`: 같은 seed는 같은 결과. `--wear0`: 착용 시작 시간(분).
- 이 폴더의 파일은 모두 `04_알고리즘 층/입력형식_v1/`에 있습니다. 팀 파일 `04_알고리즘 층/알고리즘/`은 건드리지 않았습니다.
