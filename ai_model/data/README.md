# ai_model/data

This folder holds the physics/simulation outputs behind the glucose estimation model, plus two small example datasets. **Nothing here is real sensor or clinical measurement data.** Everything is generated from simulation, Monte Carlo sampling, or analytical (Fisher-information) error models. The team's own design notes are explicit about this — see "Known limitations" below.

## Files that can feed a synthetic data generator

These are not training samples by themselves — they're the forward-model coefficients (how much each sensor signal changes per unit of glucose/temperature/thickness/etc.) and the hardware noise budget. Together they're what you'd use to replace a naive `np.random` placeholder with a physically grounded synthetic sample generator.

| File | What it is | Rows × cols |
|---|---|---|
| `EM_계수표_v1.csv` | Microwave S21 sensitivity (magnitude shift, Q change, dB/phase change at 6 frequencies 2.30–2.60 GHz) per unit change in blood permittivity, blood conductivity, skin permittivity, temperature, and clip gap thickness | 6 × 19 |
| `em_coeff_S11_v1_spectra.csv` | Full S-parameter sweep, 0.300–1.8+ GHz in 5 MHz steps: baseline S0 (complex) plus its derivative with respect to blood permittivity/conductivity, skin permittivity, temperature, at two clip-gap settings (3.5 mm, 4.5 mm) | ~300+ × 15 |
| `NIR_계수표_v1.csv` | NIR absorbance (1310/1370/1625 nm) sensitivity per +100 mg/dL glucose, +1 °C, +1 mm thickness, ×1.2 scattering, +0.02 water fraction — separate rows for phantom and earlobe geometry | 12 × 4 (+2 header rows) |
| `광자수송_v1.csv` | Monte Carlo / diffusion-model photon transport: per-wavelength sensitivity to glucose, temperature, thickness, water, scattering, across multiple source–detector geometries and two anisotropy values (g = 0.9, 0.7) | ~480 × 9 |
| `HW_노이즈_v1.csv` | Hardware noise budget: ADC, amplifier, thermal, shot, LED flicker/drift noise per wavelength, converted to glucose-equivalent error (mg/dL) for NIR-only, microwave-only, fused, and linear-model readings | 93 × 5 |
| `압력층_v1.csv` | Ear-clip force/gap operating points and person-to-person earlobe thickness variability (relaxed-lobe measurements at 2.7–4.14 mm) | 66 × 6 |

## Example labeled samples (format demo, not a training set)

| File | What it is | Rows × cols |
|---|---|---|
| `예시_frames_v1.csv` | Example per-frame output in the proposed model input format: `A_1310/1370/1625`, `S21_dB_f1–f6`, `S21_deg_f1–f6`, `ntc_dT_C`, `fsr_N`, plus a `glucose_mgdl` label, across 3 sessions × 30 frames | 90 × 37 |
| `예시_frames_flag_v1.csv` | Same frames, with an added physics-fit residual/mismatch-flag pass (`glucose_hat_mgdl`, `resid_Q`, `flag_model_mismatch`, etc.) demonstrating the false-alarm detection logic | 90 × 47 |

**These two files total 90 rows across only 3 simulated sessions.** They demonstrate the intended input format — they are not large or varied enough to train the model on, and the filename (meaning "example") reflects that.

## Design-comparison / error-budget reports (not sample data)

`구조비교_v1.csv`, `구조비교_v1_results.json`, `읽기방식_v1.csv`, `통합모델_v1.csv` compare design choices (S11 vs. S21 vs. fused; ADC reading method; averaging count) by their theoretical glucose error (mg/dL), computed from Fisher information and Monte Carlo noise draws on the physics model — not from running the trained neural network. The matching `.md` files (`EM_구조비교_v1.md`, `HW_노이즈_v1.md`, `NIR_계수표_v1.md`, `벤치예측_v1.md`, `압력층_v1.md`, `통합모델_v1.md`, `회로대조_v1.md`, `알고리즘_입력형식_기본안_v1.md`) are the human-readable write-ups of the same tables/analyses, generated by the matching `write_*_md_v1.py` script where noted in the simulation folder map — edit the script, not the `.md` file, when the model changes.

## Known limitations

These points come directly from the project's own design notes (`알고리즘_입력형식_기본안_v1.md`, `회로대조_v1.md`, `통합모델_v1.md`):

- No real sensor measurements exist yet. Every number in this folder comes from a simulation or an analytical noise model.
- A model trained only on this data should be treated as a pretraining/initialization step, not a final model — simulation-trained models are expected to need fine-tuning and validation against real measurements before deployment.
- The 6 `phys` input parameters the training notebook (`colab_training_pipeline.ipynb`) expects are **not defined anywhere in this data**.
- Even the physics model itself hasn't been checked against real measurements: the current bench LEDs don't match the model's target wavelengths, so there's no way yet to validate it against bench data.
- The trained model (`glucose_model.tflite` / `MultimodalGlucoseModel` in `colab_training_pipeline.ipynb`) has never been run against any file in this folder — the team's algorithm has not been connected to this pipeline yet.
